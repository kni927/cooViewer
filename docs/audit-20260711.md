# Codebase Audit — 2026-07-11

Scope: pre-work for (future) multi-window support and (candidate) submodule
replacement (UniversalDetector → uchardet, XADMaster → libunarr).
Report only — no code changes. Baseline: v1.3.6 + resource consolidation
(commit `ded598e`).

---

## 2a. Multi-window readiness

### Current ownership model

- **No NSDocument.** The app is a classic single-nib design: `MainMenu.xib`
  instantiates one `Controller` object (nib object id 484), which is
  simultaneously:
  - `NSApplication` delegate (`application:openFile:`, termination),
  - main window delegate (`windowWillClose:`, resize notifications),
  - the entire page-flow state machine and image-cache owner.
- Companion **nib singletons**: `BookmarkController`, `ThumbnailController`,
  `PreferenceController`, `FilterPanelController`, one `CustomWindow`
  (`window` outlet), one `CustomImageView` (`imageView`), `FullImagePanel`,
  password sheet panel.
- `main.m` is a bare `NSApplicationMain`.

### Global / shared mutable state that must become per-window

From `Controller.h` ivars (all live on the one Controller instance):

| Group | State |
|---|---|
| Book identity | `currentBookAlias/Path/Name`, `oldBook*`, `currentBookSetting` |
| Page state | `nowPage`, `sliderValue`, `completeMutableArray` (page list), `imageLoader` (COImageLoader), `marksArray`, `bookmarkArray` |
| Rendering | `firstImage`/`secondImage`/`composedImage`, `useComposedImage`, `fitMode`/`fitScreenMode`, `rotateMode`, `interpolation`, `readMode`, `singleSetting` |
| Caches / threads | `cacheArray`, `screenCacheArray`, `imageMutableArray`, lookahead `NSThread` + `lock` (NSLock) |
| Slideshow | `timer`, `timerSwitch` |
| Input maps | `keyArray*`, `mouseArray*` (could stay shared/app-wide) |

File-scope statics (process-wide; acceptable to stay global):
`Controller_input.m` — `appleRemoteHoldDown`, `dontSleepTimer`;
`COImageLoader.m` — `_COImageLoader_fileTypes/_archiveTypes` (immutable).

View→controller coupling: `AccessoryView.h` has `IBOutlet id controller`,
`CustomImageView` ↔ `AccessoryView/Window` outlets, `FullImagePanel` targets
the Controller — all wired to the singletons inside `MainMenu.xib`.

### What breaks if two windows open today

- There is no second window: the window exists only as a nib singleton.
  A second window would require programmatic creation or a separate
  window xib.
- `application:openFile:` routes every open into the same Controller and
  **replaces** the current book in the one window.
- If a second Controller were cloned naively:
  - NSUserDefaults races (recent items, bookSettings, last page —
    last-writer-wins),
  - Apple Remote / global keyboard event hooks registered twice,
  - Thumbnail/Bookmark/Preference singletons still point at one controller,
  - menu state mutation (`bookmarkMenuItem`, read-mode/sort-mode checkmarks,
    `validateMenuItem:`) assumes one active book,
  - `windowWillClose:` performs app-level persistence and slideshow
    teardown tied to "the" window,
  - lookahead threads spin-wait on per-controller `imageMutableArray`
    (`Controller.m:1710,1734,1738`) — per-instance OK, but any sharing
    corrupts.

### Effort estimate

Split into `AppDelegate` (menus, recent, defaults, remote control) +
`BookWindowController` (one xib per window owning image view, accessory
bar, thumbnail/bookmark panels, `COImageLoader`, page state). Nearly all
ivars above migrate. `Controller.m` + `Controller_input.m` ≈ 6,700 lines;
IBActions should move to the window controller so the responder chain
routes menu items to the front window. This is a large, mechanical but
risky refactor; recommend doing the "quick wins" in §2c first.

## 2b. Submodule dependency surface

### UniversalDetector

- **Zero direct call sites in app code.** The app links/embeds the
  framework only because XADMaster requires it.
- Wiring in this fork: `XADMaster/XADString.m:23` imports it by relative
  path `../UniversalDetector/UniversalDetector.h` (sibling checkout), and
  creates `[UniversalDetector new]` per `XADString` to detect filename
  byte-sequence encodings (comment notes it may return nil if the
  framework is absent).
- Consequence: swapping UniversalDetector → uchardet means editing the
  **XADMaster fork** (XADString.m), not the app. The app itself needs no
  changes for encoding detection.

### XADMaster

- All access funnels through `XADWrapper.m` / `XADItem.m`;
  the only construction site is `COImageLoader.m:388`
  (`[[XADWrapper alloc] initWithPath:]`).
- `XADArchive` APIs used: `initWithFile:`, `numberOfEntries`,
  `nameOfEntry:`, `entryIsDirectory:`, `sizeOfEntry:`, `setNameEncoding:`,
  `nameEncoding`, `contentsOfEntry:`, `isEncrypted`, `setPassword:`,
  `describeLastError`, `extractEntry:to:`, and the **private**
  `_extractEntry:as:deferDirectories:dataFork:resourceFork:`
  (`XADWrapper.m:170`) — the private call is used for extracting nested
  archives to a temp dir.
- Unused wrapper API: `initWithPath:nameEncoding:` and
  `uncompress:toTempDir:` have no callers (dead).

### Formats actually exercised

- `Info.plist` declares ~60 document types (the full libxad long tail:
  lha/lzh, sit/sitx, cab, arj, ace, zoo, Amiga disk formats, …).
  `COImageLoader` derives its accepted-extension list from
  CFBundleDocumentTypes at runtime, so everything declared is nominally
  "supported".
- Realistically exercised (docs, fixtures, JP comic usage): **zip/cbz,
  rar/cbr, 7z, tar**, plus legacy **lha/lzh** for Japanese archives.
- **libunarr covers RAR/TAR/ZIP/7z only.** Switching would drop
  lha/lzh/sit/cab and the long tail. For a Japanese-market comic viewer,
  lha/lzh is the one realistic casualty — decide whether to accept the
  regression (and prune CFBundleDocumentTypes) or keep XADMaster.
- **Encoding coupling is the riskiest part of the swap**: CP932 ZIP
  filename decoding currently happens inside XADMaster (via
  UniversalDetector). libunarr does no encoding detection, so the app
  would have to add its own uchardet pass over raw filename bytes to
  preserve today's behavior (verified working — see baseline below).

### Baseline: fixtures vs current build (2026-07-11)

All 9 archives in `tests/fixtures/generated/` open correctly in the
current Deployment build; page order matches `001→004`; Japanese
filenames (UTF-8 and CP932) decode correctly. Details recorded in
`tests/fixtures/README.md`.

## 2c. General code health

### MRC/ARC status

- **Entire app target is MRC.** No `CLANG_ENABLE_OBJC_ARC` in any build
  configuration and no per-file `-fobjc-arc` flags.
  `CLANG_ENABLE_OBJC_WEAK = YES` (MRC-weak available).
- Submodules build via their own Xcode projects (ShellScript phase);
  their memory model is out of scope.

### Memory-management bugs (in scope for a future fix, not fixed here)

1. **XADWrapper/XADItem retain cycle + per-entry leak.**
   `XADWrapper.m:29,55` do `[contentArray addObject:[[XADItem alloc]
   initWithPath:… andWrapper:self]]` — the alloc'd item is never
   released (leak), and `XADItem` retains the wrapper while the wrapper's
   array retains the item (`XADItem.m:19`), so **every opened archive
   leaks the whole XADArchive + items** for the app's lifetime.
2. **`XADWrapper.m:66`: `dealloc` calls `[archive init]`** —
   re-initializing an object during teardown; should simply be removed
   (currently mostly unreachable because of the cycle above).
3. `XADWrapper.m:49`: `[archive setNameEncoding:nil]` passes a pointer
   where `NSStringEncoding` (unsigned long) is expected
   (`-Wint-conversion`, 2 warnings). Dead path (the `nameEncoding:`
   initializer is uncalled) but wrong.

### Deprecated API usage (app code)

| API | Sites | Deprecated | Replacement |
|---|---|---|---|
| Carbon Alias Manager (`AliasHandle`, `FSRef`, `CFURLCreateFromFSRef`) | `Controller.m` (`aliasFromPath:` etc., 4 methods + callers) | 10.8 | `NSURL` bookmark data |
| `UpdateSystemActivity` | `Controller_input.m` (~2921, sleep-prevention timer) | 10.8 | `IOPMAssertionCreateWithName` |
| `NSRunAlertPanel` / `NSBeginAlertSheet` | `Controller.m`, `Controller_input.m`, `CustomImageView.m` ×3, `PreferenceController.m` ×2 | 10.10 | `NSAlert` |
| `[NSImage imageFileTypes]` | `Controller.m:741`, `COImageLoader.m:28,67` | 10.10 | `[NSImage imageTypes]` (UTIs — needs extension↔UTI mapping, not drop-in) |

Deployment build emits **44 warnings**; the majority (NSCalendarDate
family, `dataWithContentsOfMappedFile:`, `-Wsometimes-uninitialized`)
originate in the XADMaster submodule — do not fix there.

Note: pre-10.9 era patterns are otherwise pervasive but benign
(NSEnumerator loops instead of fast enumeration, `int` indexes, manual
spin-wait threading in `Controller.m:1710/1734/1738` — consider GCD when
touching multi-window).

### Dead code / junk files (delete candidates)

- `COImageLoader_temp.m` — tracked, **not compiled** (absent from the
  Xcode target). Scratch copy of COImageLoader.
- `Controller.m_1.xcclassmodel/` — Xcode 3 class-model artifact,
  contains embedded `.svn/` metadata. Pure junk.
- `MainMenu~.nib/` — legacy nib (CLAUDE.md says leave alone); also
  carries `.svn/` metadata. Unreferenced by the build.
- `Resources/info copy.plist`, `Resources/version.plist`,
  `Resources/icon2.icns`, `Resources/icon_orig.icns` — unreferenced by
  project and code (relocated during Task 1; safe to delete).
- `README.org` — stale upstream readme duplicating `README.md`.
- `en.lproj/MainMenu.strings` (now `Resources/en.lproj/`) — not part of
  any variant group in the project (MainMenu.xib group has only Base+ja).
- `XADWrapper.m`: `initWithPath:nameEncoding:`, `uncompress:toTempDir:`
  — no callers.
- Large commented-out blocks throughout (e.g. `AccessoryView.m:915-926`
  page-bar cursor code) — cosmetic.

### Build-system oddities

- **`ja.xliff` is in the Resources build phase** (pbxproj) and ships
  inside `cooViewer.app/Contents/Resources/` — it is a localization
  working file from `localize/ja.xcloc/` and should be removed from the
  phase.
- `INFOPLIST_FILE = info.plist` (lowercase) vs actual `Info.plist` —
  works on case-insensitive APFS, breaks on case-sensitive file systems.
- Project format is ancient (`objectVersion = 45`, "Xcode 3.1"); modern
  Xcode builds it fine via xcodebuild, but opening in the Xcode GUI will
  prompt for a format upgrade.
- 5 build configurations (Development, Deployment, Development2,
  Deployment2, Default) with drifted settings — consolidation candidate.

### Quick wins recommended before multi-window work

1. Fix the XADWrapper retain cycle + `[archive init]` dealloc bug
   (unbounded memory growth per opened archive).
2. Delete the dead files listed above; remove `ja.xliff` from the
   Resources phase.
3. `INFOPLIST_FILE` case fix (one-line).
4. Replace `NSRunAlertPanel`/`NSBeginAlertSheet` with `NSAlert`
   (8 sites, mechanical).
5. Migrate Alias Manager → `NSURL` bookmarks (4 methods; also removes a
   Carbon dependency).
6. `imageFileTypes` → `imageTypes` with an extension mapping helper.
