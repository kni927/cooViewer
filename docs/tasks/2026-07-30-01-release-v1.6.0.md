# v1.6.0 release: workflow fix, notarization, GitHub Release, Homebrew tap

## Goal

Ship the multi-window arc and the post-arc fixes as **v1.6.0** — a
feature-level release, not a patch. Clear the harmless error in
`xcode-build-and-release.yml`, then take it all the way through
notarization, GitHub Release, and the Homebrew tap.

**Confirm the version number with the owner before tagging** if anything
suggests a different choice. The reasoning for 1.6.0 rather than 1.5.2:
the earlier v1.5.1/v1.5.2 plan predates the multi-window arc, and MW-1
through MW-9 plus the #24/#30/#32/#33 work is far past a patch bump.

## What's shipping

- The multi-window arc (MW-1 … MW-9): multiple book windows, "Open in New
  Window…" (⌥⌘O), per-window state, native fullscreen, window restoration,
  quit-on-last-window-close.
- cvbdl QuickLook/Thumbnail support (already implemented and verified
  on-device — **not** an outstanding verification gap; no need to re-run it
  to close anything, though a post-install sanity check is cheap).
- Post-arc fixes: #24 (All Bookmark browser entry path), #30 + #33's
  password-sheet half (window-modal password prompt), #32 (no duplicate
  window when reopening a restored book from Finder), quit-while-a-
  password-prompt-is-showing.

## Step 1 — `xcode-build-and-release.yml`

1. **Diagnose the harmless error** that appears in workflow runs and clear
   it. Read the workflow and the most recent run's log; report what the
   error actually was rather than just silencing it.
2. **`softprops/action-gh-release@v3` is already set and is correct — do
   not revert it.** For context so it isn't "fixed" backwards: v2.6.2 is
   the final v2 release, unmaintained, and runs on the Node 20 runtime
   GitHub Actions deprecated; v3 moved to Node 24 and is what the project
   directs users to. Latest is v3.0.2. **A plausible hypothesis worth
   checking first: the harmless error was the Node 20 deprecation notice,
   and the v3 bump already resolves it.** Verify before hunting further.
3. While in the file, check whether any *other* pinned action is on a
   deprecated runtime and would produce the same class of notice.
4. **Confirm Actions are actually enabled for this repository** — they are
   disabled by default on forks and must be turned on manually. A release
   workflow that never runs is a silent failure mode.
5. Do a dry/validation run if one can be done without cutting a release,
   so the workflow is known-good *before* a tag triggers it.

## Step 2 — pre-release code and docs

1. **Version bump** in the project's `Info.plist`
   (`CFBundleShortVersionString` / `CFBundleVersion`) and anywhere else the
   version is carried.
2. **Record as known issues, do not fix** (decided): the three
   "can't quit while modal X is up" cases —
   - the All Bookmark browser (`runModalForWindow:`),
   - the nested-archive password prompt (quit is **deferred, not
     discarded** — answering the prompt then fires the quit; unfixable
     without overturning the decision to keep that prompt synchronous),
   - the archive-load progress sheet (Cmd+Q swallowed by the modal
     session; an AppleEvent quit works immediately).

   Note that `COApplication`'s `-terminate:` interception is the mechanism
   that could be extended to them later.
3. **Also record:** the All Bookmark browser has no
   select-a-bookmark-to-jump-to-that-page gesture and never did — the
   Open button acts on a *book* selection. This is a feature gap left to
   an owner decision, not a defect.
4. **Release notes / changelog** covering the arc. This is the largest
   user-visible change in the project's history — the notes deserve real
   effort, not a commit-list dump. Draft them for the owner to review
   before publishing.
5. Final `docs/DEV_LOG.md` and `docs/KNOWN_ISSUES.md` update.

## Step 3 — build, sign, notarize

1. Clean Deployment build; confirm the warning baseline is unchanged
   (312 lines = 310 source + 2 "not stripping binary").
2. **Sign bottom-up** — extensions before the host app. This is the CI
   codesigning gotcha already hit once in this project: the QuickLook
   sandbox entitlements require bottom-up signing order.
3. Notarize through the existing Apple Developer Program setup and
   **staple** the ticket.
4. Verify: `spctl -a -vvv` on the built app, `stapler validate`, and
   confirm the extensions inside the bundle are signed as expected.
5. **Reuse the existing credential/secret setup — introduce no new
   authentication mechanism.** If a secret appears to be missing or
   expired, stop and report; do not create or substitute credentials.

## Step 4 — GitHub Release

1. Tag and push; let the workflow produce the release.
2. Confirm the uploaded asset is the notarized, stapled build — not an
   intermediate artifact.
3. Record the asset's SHA256 (needed for the tap).

## Step 5 — Homebrew tap

1. Update the formula in the `kni927/tap` tap for `cooviewer`: version,
   URL, and sha256.
2. Test a real install from the tap on this machine and confirm the
   installed app launches, is Gatekeeper-clean without `xattr -cr`, and
   that the QuickLook/Thumbnail extensions resolve to the newly installed
   bundle (this install supersedes the 1.5.0 copy in `/Applications` that
   previously held LaunchServices precedence — a good moment for a quick
   `.cvbdl` and `.cbz` thumbnail sanity check).

## Out of scope

- The README rewrite from the original author's manuals — a separate
